---
title: Limitations
description: Trust and operational limits of the FORGE sandbox.
---

FORGE is a prototype. It runs on a local stack, and its program is deployed on Solana Devnet for demonstration with test assets only. These limits apply to everything in the repository today.

## Assets and keys

- `FORGE_TEST_USD` is a fixture label. It is not redeemable currency, a certified security or a transferable loan instrument.
- Fixtures generate independent demonstration wallets. The LiteSVM fixture holds them only in memory. The seed writes their keys to the ignored `.local/demo/session.json` (`.local/devnet/` on Devnet) so the console and the end-to-end run can sign as each role. No real bank or customer data is needed.
- The fixture treasury keeps mint authority and can issue more test tokens.

## Program behavior

- Creating a vault does not certify a bank.
- Vault rules govern FORGE instructions, not every transfer of the underlying token.
- Direct token donations increase vault cash. They do not count as repayment and do not change loan state.
- Pausing disbursements stops new draws only. Repayment, funding and treasury withdrawals continue; a withdrawal still needs both approvers.
- Funding is deduplicated per `Idempotency-Key` only. Two funding requests with different keys both transfer, even with the same amount and source.

## Deployment

- Locally, the program is loaded at genesis of a disposable loopback `solana-test-validator`.
- On Devnet the program is `CktNaBZSqpvStJtXVm7Jtjs47L2JqWd66564CV3HLwdx`, deployed with the upgradeable loader. Its upgrade authority, `FQM2nPX3s8TchNDfhzLD1Gj61AWA8CUKuaVDE5BdXcQq`, can replace the program at any time, so the deployed program is not immutable. There is no mainnet deployment. See [Devnet](/docs/devnet) for the deployment record.
- LiteSVM is not a local validator. Program tests use LiteSVM; the service flow is validated on the loopback validator.

## Not yet built

- Production custody (HSM/MPC) integration and wallet-adapter signing; the console signs with browser-held demo keys
- Bank-core integration beyond signed webhooks
- Program events, receipts for treasury funding, approver rotation and withdrawal cancellation
- Partial repayments and accrual
- An external security audit
